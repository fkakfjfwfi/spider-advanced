02 · 请求的艺术：urllib / requests / 正则

第 01 章你学会了"看懂请求"，这一章学会"发出请求"：从标准库 urllib 走到事实标准 requests，把 GET/POST、响应处理、Session、超时重试、SSL、上传下载、代理九大件全部打通；再用正则把响应文本里的数据抠出来，最后用一套完整的猫眼 TOP100 实战收尾——抓下来、解析好、存成 CSV。

🔗 连接你已有的知识（考研 408 · 计算机网络 × 离散数学）

· requests 并没有发明新东西：它是对套接字 API（socket）之上的 HTTP 报文封装——408 网络编程里你手写过的"连接 → 发报文 → 收报文"，requests 帮你拼报文、管连接池、解 Cookie，本质没变；
· URL 编码（%E4%BD%A0）就是计网"统一资源定位符 + 百分号编码"考点，params 参数自动替你做了这件事；
· 正则表达式是形式语言与自动机思想的实用化：每条正则等价于一台有限状态自动机（NFA/DFA），.*? 的非贪婪回溯正是状态机的转移过程——408 里考过的"字符串模式匹配"在这里天天用；
· 学完这章你会发现：库是外壳，HTTP 语义才是内核——这正是上一章的回报。

2.1 urllib 与历史演进 对齐教材 3.1

urllib 是 Python 的标准库HTTP 工具集（urllib.request 发请求、urllib.parse 拼 URL、urllib.error 收异常），不需要 pip 安装。在 requests 诞生之前，它是唯一的正牌选择。先看用它发一个带请求头的请求有多"虔诚"：

urllib_demo.py
from urllib import request, error
import socket

url = "https://httpbin.org/get"
headers = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"}

req = request.Request(url, headers=headers)   # 必须"先造一个 Request 对象"才能带头
try:
    with request.urlopen(req, timeout=10) as resp:
        print(resp.status)                    # 200
        print(resp.read()[:120])              # 注意：拿到的是 bytes，要自己 decode
except error.HTTPError as e:                 # 服务器有响应但状态码是 4xx/5xx（子类，放前面接）
    print("HTTP 错误:", e.code, e.reason)
except error.URLError as e:                  # 连不上/域名解析失败/被拒（父类，放后面接）
    print("URL 错误:", e.reason)
except socket.timeout:
    print("请求超时")

能感受到它的繁琐：读出来是 bytes 要手动解码、Cookie 要自己用 http.cookiejar 管、没有会话概念、异常体系要背"HTTPError 是 URLError 的子类、先接子类"。所以整个社区转向了 requests——它的口号是 "HTTP for Humans"：同样的请求三行搞定，响应自动解码，Cookie 自动管理，异常统一成一个 requests.RequestException 基类。

urllib 的今天定位：不是"学了没用"，而是①它是 requests 底层栈（requests → urllib3 → socket）的一环，读懂它有助于诊断底层问题；②urllib.parse（quote / urlencode / urlparse）至今仍是拼 URL 的标准工具，2.2 节马上用；③受限环境（不能装第三方包的服务器）里它是兜底。定位一句话：了解即可，parse 必会，异常模型要懂。

2.2 requests 全面精讲 对齐教材 3.2 本章重点

安装：pip install requests。下面按"九大件"把它讲透——这九件覆盖了静态爬虫 95% 的场景，每一件都配可运行代码。

① GET 与 params：让库替你编码

GET 的参数拼在 URL 查询串里。自己手拼有两个坑：中文/空格没编码直接 400；参数值里带 & 会被当成下一个参数的起点。requests 的 params 参数自动完成百分号编码：

get_params.py
import requests

resp = requests.get(
    "https://httpbin.org/get",
    params={"kw": "你好 世界", "page": 1, "tag": "科幻&悬疑"},
    timeout=10,
)
print(resp.url)
# https://httpbin.org/get?kw=%E4%BD%A0%E5%A5%BD+%E4%B8%96%E7%95%8C&page=1&tag=%E7%A7%91%E5%B9%BB%26%E6%82%AC%E7%96%91
#   中文 → 百分号编码，空格 → +，& → %26：参数值不再被截断

如果坚持手拼 URL，必须用 urllib.parse 先编码，别裸拼：

from urllib.parse import quote, urlencode

kw = "你好 世界"
bad  = f"https://httpbin.org/get?kw={kw}"                  # ❌ 中文空格裸奔，部分服务器直接 400
ok1  = "https://httpbin.org/get?" + urlencode({"kw": kw})   # ✅ 多参数用 urlencode
ok2  = f"https://httpbin.org/get?kw={quote(kw)}"           # ✅ 单参数用 quote（空格变 %20）

② POST：data 表单 vs json 参数

POST 的参数在请求体里，格式由你选的参数决定——这是新手最常见的 400 根源：

写法请求体格式自动携带的 Content-Type典型场景
data={"k": "v"}k=v&k2=v2application/x-www-form-urlencoded传统表单、登录、老接口
json={"k": "v"}{"k":"v"}（自动序列化）application/json现代 API、Ajax 接口（第 05 章主战场）
data=json.dumps(d) + 手写头自定义需手动声明要精细控制请求体时
post_demo.py
import requests, json

# 表单方式：服务器收到 user=bob&pwd=123
requests.post("https://httpbin.org/post", data={"user": "bob", "pwd": "123"}, timeout=10)

# JSON 方式：服务器收到 {"user": "bob", "pwd": "123"}，头部自动是 application/json
requests.post("https://httpbin.org/post", json={"user": "bob", "pwd": "123"}, timeout=10)

# 等价于 json= 的手写版——理解"格式由 Content-Type 声明"这件事
requests.post("https://httpbin.org/post",
              data=json.dumps({"user": "bob"}),
              headers={"Content-Type": "application/json"}, timeout=10)
接口返回 400 先查这里：接口要 JSON 你却用 data= 发了表单（或反过来）。排查神器：print(resp.request.headers) 和 print(resp.request.body)——PreparedRequest 会告诉你实际发出去的头和体。

③ 响应对象：text / content / json() / encoding

拿到 resp 之后，这几个属性就是你的全部世界：

resp_demo.py
resp = requests.get("https://httpbin.org/json", timeout=10)

resp.status_code        # 200
resp.reason             # 'OK'
resp.headers["content-type"]   # 响应头字典，键大小写不敏感
resp.text               # str —— 按 resp.encoding 解码后的文本（网页用它）
resp.content            # bytes —— 原始字节（图片、文件用它）
resp.json()             # 直接反序列化（本质 = json.loads(resp.text)）
resp.url                # 最终 URL（跟随重定向之后）
resp.history            # 重定向轨迹，登录跳转分析有用
resp.cookies            # 服务器种下的 Cookie

乱码修正是 text 的高频翻车点。requests 猜编码的顺序是：响应头里的 charset → 没有就回退 ISO-8859-1（这是 HTTP 规范对纯文本的默认值，但现实网站常常不守规矩）。修正方法：

fix_encoding.py
resp = requests.get("https://example.com/old-page", timeout=10)
print(resp.encoding)             # ISO-8859-1 ← 头里没写 charset 时的回退值，中文全乱
resp.encoding = resp.apparent_encoding   # chardet 根据字节特征猜出的真实编码（utf-8/gbk…）
print(resp.text[:100])           # 正常中文

# 注意：text 是"首次访问才解码并缓存"的——所以改 encoding 必须发生在第一次用 text 之前
# 或者绕过 text，直接对字节解码：html = resp.content.decode("utf-8")

④ 自定义 headers：全套抄写法

第 01 章讲过：requests 默认 UA 是 python-requests/x.x，一眼假。标准做法是打开 F12 → Network → 选中目标请求 → 右键 Copy → Copy request headers（或 Copy as cURL 再转换），把关键头部抄进字典。引擎级的四件套是 UA、Referer、Cookie、Accept：

headers_demo.py
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                  "(KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36",
    "Referer": "https://example.com/",          # 防盗链就查它，直连接口被拒先补它
    "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
    "Accept-Language": "zh-CN,zh;q=0.9",
    "Cookie": "sessionid=从F12抄来的值; tz=Asia/Shanghai",  # 登录态直接注入
}
resp = requests.get("https://example.com/", headers=headers, timeout=10)
# 头部键名大小写不敏感；值里的引号、分号原样传输，照抄即可

⑤ Session 会话：一次创建全程复用

呼应 1.4：HTTP 无状态，登录态靠 Cookie 续命。requests.Session() 把"收 Cookie → 存 → 回带"自动化，还顺带复用底层 TCP 连接（keep-alive），又对又快。工程习惯是每个爬虫脚本都建一个 Session，把公共 headers、代理、重试策略都挂在它身上：

session_demo.py
import requests

s = requests.Session()
s.headers.update({"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"})  # 会话级默认头

s.get("https://httpbin.org/cookies/set/token/abc123", timeout=10)  # Set-Cookie 自动收下
print(s.get("https://httpbin.org/cookies", timeout=10).json())
# {'cookies': {'token': 'abc123'}} —— 后续请求自动携带，无需手动管理

# 也可以从浏览器抄登录态直接注入（F12 → Application → Cookies）
s.cookies.update({"sessionid": "从浏览器抄来的值"})

⑥ 超时与重试：爬虫的保命符

timeout 必须显式给（不给 = 永久等待，爬虫挂死一整夜的经典事故）。它可以是元组 (连接超时, 读取超时)：连接超时管 TCP 握手（对应 408 的三次握手耗时），读取超时管"连上了但服务器迟迟不回数据"。重试要讲究章法：网络抖动和 5xx 值得重试，4xx 是"业务拒绝"，重试只会让封禁升级。

retry_manual.py
import time, random, requests

def get_with_retry(url, retries=3, **kwargs):
    """手动重试：只重试网络异常与 5xx；4xx 直接返回交给上层判断"""
    kwargs.setdefault("timeout", (3, 10))          # (连接超时, 读取超时)
    last_exc = None
    for attempt in range(1, retries + 1):
        try:
            resp = requests.get(url, **kwargs)
            if resp.status_code < 500:
                return resp                      # 2xx 成功；4xx 重试也不会好
            last_exc = requests.HTTPError(f"HTTP {resp.status_code}")
        except requests.RequestException as e:   # 连接/超时/代理异常的公共基类
            last_exc = e
        wait = 2 ** attempt + random.random()    # 指数退避 + 随机抖动：2s、4s、8s…
        print(f"第 {attempt} 次失败：{last_exc}，{wait:.1f}s 后重试")
        time.sleep(wait)
    raise last_exc

# 输出示例：
# 第 1 次失败：HTTP 502 Server Error，2.3s 后重试
# 第 2 次失败：HTTP 502 Server Error，4.7s 后重试
# （第 3 次成功则返回 resp）

不想自己写循环？把重试策略挂到 Session 的适配器上，交给 urllib3 自动执行：

retry_urllib3.py
from requests import Session
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(
    total=3,                                # 总重试次数
    backoff_factor=0.5,                     # 退避间隔：0.5s、1s、2s…
    status_forcelist=[500, 502, 503, 504],  # 只有这些状态码才触发重试
    allowed_methods=frozenset({"GET", "POST"}),  # 允许重试的方法（旧版 urllib3 叫 method_whitelist）
)
adapter = HTTPAdapter(max_retries=retry)
s = Session()
s.mount("https://", adapter)                # 挂到对应协议前缀上，全局生效
s.mount("http://", adapter)

⑦ SSL：verify=False 的坑与警告抑制

requests 默认校验服务器证书（验签 + 验域名）。爬自签名证书的内网测试站、或证书配置有误的老站，会直接抛 SSLError。临时跳过用 verify=False：

ssl_demo.py
import requests, urllib3

resp = requests.get("https://self-signed.example.com", verify=False, timeout=10)
# 每次都会刷警告 InsecureRequestWarning，测试期可以关掉：
urllib3.disable_warnings(urllib3.exceptions.InsecureRequestWarning)

# 正确姿势：带上自己的 CA 证书包做校验（而不是关掉校验）
# requests.get(url, verify="/path/to/certfile.pem")
verify=False 关掉的是"验证"，不是"加密"：数据仍然加密传输，但你无法确认对面是不是真服务器——中间人（408 安全考点）可以截获并篡改内容。仅限测试环境使用；代码合入前全局搜索 verify=False，一个都不许留在生产里。

⑧ 文件上传与二进制下载

上传用 files=（三元组：字段名、文件名、文件对象/MIME）；下载小文件直接 content，大文件用 stream=True + iter_content 分块写盘，内存占用恒定：

upload_download.py
import requests

# ① 文件上传
with open("avatar.png", "rb") as f:
    requests.post("https://httpbin.org/post",
                  files={"file": ("avatar.png", f, "image/png")}, timeout=10)

# ② 小图直接拿字节
img = requests.get("https://httpbin.org/image/jpeg", timeout=10)
with open("cover.jpg", "wb") as f:      # 注意 "wb" 二进制写
    f.write(img.content)

# ③ 大文件流式下载：内存里永远只有 8KB
resp = requests.get("https://example.com/big-video.mp4", stream=True, timeout=(3, 30))
with open("big-video.mp4", "wb") as f:
    for chunk in resp.iter_content(chunk_size=8192):
        f.write(chunk)

⑨ 代理 proxies

呼应 1.5：代理让目标站看到的是代理的 IP。requests 里就是传一个字典，http/https 各配一条；带认证的代理把账号密码写进 URL：

proxy_demo.py
proxies = {
    "http":  "http://127.0.0.1:7890",
    "https": "http://127.0.0.1:7890",   # https 流量走的隧道同样由 http 代理承载
}
# 带认证：proxies = {"http": "http://user:pass@1.2.3.4:8080", "https": "http://user:pass@1.2.3.4:8080"}
print(requests.get("https://httpbin.org/ip", proxies=proxies, timeout=10).text)
# {"origin": "代理服务器的 IP"}
🌐 多源视角 · Mitchell《Python网络爬虫权威指南》：彻底解决编码与乱码

乱码不是玄学，根源只有两种：① 服务器声明的 charset 与实际不符（头里说 ISO-8859-1，字节其实是 GBK）；② 服务器压根没声明——HTTP 规范让 text/* 回退 ISO-8859-1，浏览器会自己猜 UTF-8，requests 也在猜，猜的依据不同，就出现"浏览器正常、爬虫乱码"。requests 给了你两个编码入口：resp.encoding（来自响应头声明，没声明就回退 ISO-8859-1）与 resp.apparent_encoding（requests 2.26+ 内置 charset_normalizer，旧版用 chardet，按字节特征猜）。
Mitchell 推崇的处理思路是社区著名的 "Unicode 三明治"原则（出自 Ned Batchelder 的经典演讲，被爬虫教材广泛引用）：入口处尽早 decode 成 str → 中间处理全程用 unicode → 出口处最后才 encode。乱码事故几乎都发生在"bytes 和 str 混着处理"的地带，把边界收干净，乱码自然绝迹。

robust_text.py —— 三级策略，终结乱码玄学
import requests

def get_text(url, headers=None, timeout=10):
    """返回解码正确的文本：声明可信就信，不可信就探测"""
    resp = requests.get(url, headers=headers or {}, timeout=timeout)
    resp.raise_for_status()

    # ① 头里明确声明了 charset（且不是规范的默认回退值）→ 直接信它
    if resp.encoding and resp.encoding.lower() != "iso-8859-1":
        return resp.text

    # ② 没声明 / 瞎声明 → charset_normalizer 按字节特征猜（返回解码好的字符串）
    import charset_normalizer
    best = charset_normalizer.from_bytes(resp.content).best()
    if best:
        return str(best)

    # ③ 兜底：国内站点常见编码逐个试；坏字节用 ? 占位，绝不让程序崩
    for enc in ("utf-8", "gb18030", "big5"):
        try:
            return resp.content.decode(enc)
        except UnicodeDecodeError:
            continue
    return resp.content.decode("utf-8", errors="replace")
九大件串成一句话：Session（⑤）挂好 headers（④）与 Retry（⑥），GET 带 params（①）、POST 分清 data/json（②），响应用 text/content/json()（③）解析，上传下载走 files/iter_content（⑧），过墙走 proxies（⑨），SSL 别乱关（⑦）。第 07 章的代理池、第 05 章的接口直连，全是这九件的排列组合。

2.3 正则表达式系统精讲 对齐教材 3.3

解析库（下一章）负责"按结构定位"，正则负责"按字符模式硬捞"——它是最后的安全网：HTML 被压成一行、数据藏在 JS 变量里、接口返回奇形怪状的文本，正则都还能用。import re 之后，先背元字符速查表：

元字符速查表

元字符含义示例
.任意字符（换行符除外，配 re.S 可含）a.c → abc / a1c
^ / $字符串开头 / 结尾^\d+$ → 整行是数字
*前一项重复 0 次或多次ab* → a / ab / abbb
+前一项重复 1 次或多次ab+ → ab / abbb
?前一项出现 0 或 1 次；跟在量词后变非贪婪colou?r → color / colour
{n,m}重复 n 到 m 次\d{4}-\d{2} → 2026-10
[abc] / [^abc]字符集 / 反集（任选其一 / 除它们之外）[0-9a-f] → 十六进制位
|或cat|dog → cat 或 dog
()分组（findall 只返回组；配 ?P<名字> 成命名分组）(\d+)-(\d+)
\d \w \s数字 / 字母数字下划线 / 空白（大写 \D \W \S 取反）\w+ → 单词

五大函数：match / search / findall / finditer / sub

函数行为返回值爬虫用途
re.match(p, s)从字符串开头匹配Match 对象或 None校验整串格式
re.search(p, s)扫描全文找第一个匹配Match 对象或 None取单个值（标题、token）
re.findall(p, s)找全部匹配字符串列表；有分组时返回分组的元组列表批量提取列表数据（最常用）
re.finditer(p, s)findall 的迭代器版逐个 yield Match 对象大文本省内存、需要位置信息
re.sub(p, repl, s)替换所有匹配替换后的字符串清洗数据：去标签、去空白

常用旗标： re.S 让 . 匹配换行（跨行 HTML 必备）、re.I 忽略大小写、re.M 多行模式。

贪婪与非贪婪：爬虫第一正则考点

量词默认贪婪：尽可能多吃。配合 HTML 提取时几乎永远要加 ? 变非贪婪：

greedy.py
import re

html = '<h3 class="title">三体</h3><h3 class="title">活着</h3>'

print(re.findall(r'class="title">(.*)</h3>', html))
# ['三体</h3><h3 class="title">活着']  ← 贪婪：.* 一路吃到最后一个 </h3>

print(re.findall(r'class="title">(.*?)</h3>', html))
# ['三体', '活着']                     ← 非贪婪：吃到第一个满足处就停

记忆模型：.*? 的策略是"先一口不吃，看后面能不能配上；配不上才吐出一个字符再试"——这正是自动机的回溯。

分组、命名分组与 compile

groups.py
import re

# 普通分组：findall 返回元组列表，按位置取
pairs = re.findall(r'(\d{4})-(\d{2})-(\d{2})', "发布于 2026-10-25，截止 2026-11-01")
print(pairs)                      # [('2026', '10', '25'), ('2026', '11', '01')]

# 命名分组：?P<名字> —— 字段多时按名字取，可读性高
m = re.search(r'(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})', "发布于 2026-10-25")
print(m.group("year"), m.group("month"), m.group("day"))   # 2026 10 25

# compile 预编译：同一条正则反复用（翻页循环里）时更快、更好维护
DATE_RE = re.compile(r'\d{4}-\d{2}-\d{2}')
print(DATE_RE.findall("2026-10-25 和 2026-11-01"))        # ['2026-10-25', '2026-11-01']

⚠️ 正则的边界：什么时候正则会害你

正则是好刀，但有两根红线，撞上轻则解析错数据，重则程序卡死：

红线①：HTML 不是正则语言，嵌套结构用正则解析注定脆弱。正则语言在形式语言里天生表达不了"任意深度的配对"，所以"匹配最外层 div 的完整内容"这类需求，正则只能对固定层数凑合，层数一变立刻失效：

nested_trap.py
import re

html = '<div id="a"><div id="b">正文</div></div>'

# 想取"最外层 div 的完整内容"：
m = re.search(r'<div id="a">(.*)</div>', html)
print(m.group(1))
# <div id="b">正文</div>   ← 贪婪把内层闭合标签也吞了，"配对"配错了对象

# 换成三层嵌套就彻底无解：<div[^>]*>((?:(?!</div>).)*)</div> 这类仿递归写法
# 只对固定层数有效，层数一变立刻失效——正则语言天生表达不了任意深度的配对。
# 正确姿势：结构提取交给解析器建树（下一章），正则只做最后的字符级兜底。

红线②：灾难性回溯（catastrophic backtracking）。嵌套量词（量词套量词）会让回溯路径指数爆炸——模式 (a+)+b 对付 30 个 a 的文本，状态机要枚举约 2^30 种拆分方式，直接卡死：

backtracking.py
import re

text = "a" * 30 + "c"        # 30 个 a，末尾故意不是 b（逼回溯走到底）

# ❌ 千万别真跑：re.match(r"(a+)+b", text) —— 嵌套量词，几分钟到"跑不完"都有可能
# ❌ 同族危险模式：r"(\d+)+$"、r"(a|a)*b"、r"(.*a){20}" —— 一切"量词套量词"

# ✅ 展平量词：同一个意图，一层量词，毫秒级返回 None
print(re.match(r"a+b", text))                    # None

# ✅ 真需要嵌套语义：第三方 regex 模块的占有量词 a++（吞掉后绝不回退）
# pip install regex 后：regex.match(r"(a++)+b", text) —— 立刻失败而不是卡死
安全守则：① 量词永远不套量词，能展平就展平；② Python 标准库 re 不支持占有量词与原子组，需要时用第三方 regex 模块（a++、(?>…)）；③ 给量词设上限（.*? 换成 [^<]{1,200}?），把回溯空间锁死；④ 结构化提取交给解析库，正则只在"压缩成一行、JS 变量"这类短文本里作战。

第三步：完整代码（教材版：requests + 正则）

maoyan_top100.py
import csv
import re
import time
import random
import requests

HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                  "(KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36",
}

# 一条正则吃掉一个 <dd>：每组对应一个字段，re.S 让 . 能跨行
PATTERN = re.compile(
    r'<dd>.*?board-index.*?>(\d+)</i>'      # ① 排名
    r'.*?title="(.*?)"'                     # ② 片名（第一个 title 属性）
    r'.*?star">\s*(.*?)\s*</p>'             # ③ 主演
    r'.*?releasetime">(.*?)</p>'            # ④ 上映时间
    r'.*?integer">(.*?)</i>'                # ⑤ 评分整数部分
    r'.*?fraction">(.*?)</i>'               # ⑥ 评分小数部分
    r'.*?</dd>', re.S)

def parse_page(html):
    """把一页 HTML 解析成字典列表"""
    rows = []
    for m in PATTERN.finditer(html):
        rank, title, stars, release, int_part, frac_part = m.groups()
        rows.append({
            "排名": rank,
            "片名": title,
            "主演": stars.replace("主演：", "").strip(),
            "上映时间": release.replace("上映时间：", ""),
            "评分": int_part + frac_part,     # '9.' + '7' → '9.7'
        })
    return rows

def main():
    with open("maoyan_top100.csv", "w", newline="", encoding="utf-8-sig") as f:
        writer = csv.DictWriter(f, fieldnames=["排名", "片名", "主演", "上映时间", "评分"])
        writer.writeheader()
        total = 0
        for page in range(1, 11):                 # 翻页公式：offset = (page-1)*10
            url = f"https://www.maoyan.com/board/4?offset={(page - 1) * 10}"
            resp = requests.get(url, headers=HEADERS, timeout=10)
            resp.raise_for_status()               # 非 2xx 直接抛异常，防脏数据
            rows = parse_page(resp.text)
            writer.writerows(rows)
            total += len(rows)
            print(f"第 {page} 页：抓到 {len(rows)} 条")
            time.sleep(random.uniform(1, 2))     # 礼貌延时：别把人家打挂
        print(f"✅ 已保存 {total} 条到 maoyan_top100.csv")

if __name__ == "__main__":
    main()

import parsel

def parse_page(html):
    sel = parsel.Selector(html)
    rows = []
    for dd in sel.xpath('//dl/dd'):
        rows.append({
            "排名": dd.xpath('./i/text()').get(),
            "片名": dd.xpath('.//p[@class="name"]/a/@title').get(),
            "主演": (dd.xpath('.//p[@class="star"]/text()').get("") or "").replace("主演：", "").strip(),
            "上映时间": (dd.xpath('.//p[@class="releasetime"]/text()').get("") or "").replace("上映时间：", ""),
            "评分": "".join(dd.xpath('.//p[@class="score"]/i/text()').getall()),
        })
    return rows

工程建议解析库为主，正则为兜底：结构化提取交给 XPath；只有 JS 变量、压缩成一行的字符串才动用正则
本章避坑清单：① verify=False 只许在测试环境用，且关闭告警（disable_warnings）之后连"你正在裸奔"的提示都没了——合入前全局搜一遍；② resp.text 乱码先查 resp.encoding（头里没写 charset 就回退 ISO-8859-1），改编码要赶在第一次访问 text 之前，或干脆 resp.content.decode("utf-8")；③ resp.json() 只对 application/json 响应有效，text 是 str、content 是 bytes，别混用（bytes 没有切片后 decode 再 json 的连环坑）；④ params 与手拼 URL 混用会双重编码——已编码的 %E4 会被再编码成 %25E4，编码只做一次，params 和手拼二选一；⑤ 忘了 timeout 或只给一个数：连接卡死和读取卡死是两种病，用元组 (3, 10) 分别设限。

2.5 更进一步：TLS 指纹与 curl_cffi 进阶

进阶玩家都遇到过这个灵异现象：headers 全对、Cookie 全带、频率正常，请求依然被拒——甚至在 TCP 连上之后就被服务器掐断。原因不在 HTTP 层，而在更底下的 TLS 握手：客户端打招呼（ClientHello）时会报出自己的 TLS 版本、加密套件列表、扩展、椭圆曲线等一串参数，服务器把它们拼起来算个 MD5，就是业界通用的 JA3 指纹。requests 走的 OpenSSL 栈有稳定的默认参数组合，JA3 一眼就能认出"这不是浏览器"——报文伪装得再像，握手阶段就先暴露了。这正是韦世东《Python3反爬虫原理与绕过实战》里"指纹对抗"思想的现代延续：反爬早已从"看请求头"进化到"看握手特征"。

curl_cffi_demo.py
# pip install curl_cffi —— 基于 curl 的 TLS 实现，可 impersonate 主流浏览器
from curl_cffi import requests

# impersonate="chrome"：连 TLS ClientHello + HTTP/2 帧特征一起伪装成 Chrome
resp = requests.get("https://example.com/", impersonate="chrome", timeout=10)
print(resp.status_code)      # 之前 403/被掐断的站，现在可能就是 200

# 同样支持 Session 用法，API 与 requests 基本一致
s = requests.Session(impersonate="chrome")
r = s.get("https://example.com/page", timeout=10)
使用边界：TLS 指纹伪装是双刃剑——同样的技术也可能被用于绕过你无权访问的系统。curl_cffi 只在合法场景使用：采集你有权访问的公开数据、做安全测试或兼容性调试；商业风控站点请先读 robots 与服务条款。工具越强，责任越重。

Q1requests 已经一统天下，urllib 还有必要学吗？它的今天定位是什么？概念

考点：对齐教材 3.1，对工具生态的分层理解。

先想清楚调用栈：requests → urllib3 → 标准库 socket。urllib 是标准库层的 HTTP 封装，requests 是它之上的人性化外壳。

参考解析：仍有必要，但定位是"了解即可、parse 必会、异常模型要懂"：① 理解分层——requests 底层就是 urllib3，很多报错（ConnectionError、ReadTimeout）顺着栈能追到 urllib/urllib3 的异常体系；② urllib.parse（quote/urlencode/urlparse）不依赖任何第三方包，是拼 URL、解析回调地址的通用工具；③ 受限环境（不给装第三方库的服务器、面试手写）里 urllib 是兜底；④ 维护老项目会直接遇到。它被取代的是"日常写爬虫"这个位置，不是知识本身。
Q2同一个接口，用 data= 发就 400，用 json= 发就 200。为什么？如何自查"我实际发出去了什么"？分析

考点：2.2② 的 data/json 之辨 + PreparedRequest 排查法。

参考解析：根因是请求体格式与 Content-Type 和服务器期望不符：data= 发的是 k=v&k2=v2 且头是 x-www-form-urlencoded；json= 发的是 JSON 字符串且头是 application/json。现代接口大多按 Content-Type: application/json 路由解析，收到表单体解析失败返回 400。自查三板斧：print(resp.request.headers)、print(resp.request.body) 看实际发出的头和体；或把请求打到 https://httpbin.org/post，响应会原样回显你发出的 json/data 与头部，一对比就现形。修复：按接口文档改用 json=（或手写 data=json.dumps(...) + Content-Type 头）。
Q3动手：从文本 "联系人: zhangsan@example.com，发布于 2026-10-25，浏览量 1024 次" 中提取邮箱、日期（年/月/日用命名分组）和所有数字。动手

import re

text = "联系人: zhangsan@example.com，发布于 2026-10-25，浏览量 1024 次"

# ① 邮箱：字符集 + @ + 域名
print(re.findall(r'[\w.+-]+@[\w-]+\.[\w.]+', text))
# ['zhangsan@example.com']

# ② 日期：命名分组，按名字取
m = re.search(r'(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})', text)
print(m.group("year"), m.group("month"), m.group("day"))
# 2026 10 25

# ③ 所有数字串
print(re.findall(r'\d+', text))
# ['2026', '10', '25', '1024']

Q4动手：设计实验复现"双重编码"——把已经编码过的 URL 再交给 params 会发生什么？给出修复原则。动手

考点：2.2① 与避坑④：编码责任归属。

参考解析：requests 对 params 的每个值都会做一次百分号编码，而 % 本身是要被编码的字符，于是已编码串里的 %E4 变成 %25E4：
import requests

already = "%E4%BD%A0%E5%A5%BD"     # "你好" 的正确编码
resp = requests.get("https://httpbin.org/get", params={"kw": already}, timeout=10)
print(resp.url)
# https://httpbin.org/get?kw=%25E4%25BD%25A0%E5%25A5%25BD
# 服务器解码一次得到字面量 "%E4%BD%A0%E5%A5%BD"，而不是 "你好" —— 搜索/查询直接失败

修复原则：编码只做一次，责任只归一方。要么把原始中文交给 params（推荐，requests 负责编码）；要么全程手拼并自己 quote()。从 F12 复制的现成 URL 里如果已经带编码参数，就直接放进 URL 字符串，不要再拆给 params。
