03 · 解析库全解：XPath / BeautifulSoup / pyquery

抓下来只是第一步，数据要从结构里"精准抠"出来。这一章把四大解析方案一次讲全：XPath（功能最强）、BeautifulSoup（对新手最友好）、pyquery（jQuery 风格）、parsel（Scrapy 同源、工程首选），外加 JSON 数据解析；配一个能亲手练选择器的游乐场和一集解析器动画。学完你将拥有"拿到任何 HTML 都知道用什么表达式取什么数据"的手感。

🔗 连接你已有的知识（考研 408 · 数据结构）

· 解析器做的事，本质是把你 408 数据结构课里熟悉的树搬进浏览器：HTML 文本 → DOM 树，每个标签是一个节点，父子/兄弟/先辈/后代关系与树的结构术语一一对应；
· XPath 的 // 与轴（ancestor/descendant/sibling）就是树的遍历与亲戚查询——树的先序遍历正是 DOM 的解析顺序，谓词 [position()<=3] 是"取前 k 个孩子"；
· CSS 选择器 / XPath 谓词 = 树上的索引查询：与其自己写递归遍历，不如用一门"坐标语言"直接描述目标节点；
· 顺带一句编译原理：HTML 解析器 = 词法分析（切 token）+ 语法分析（建树）的现成实现——解析器报"标签未闭合"时，你听到的就是语法分析器的抱怨。

3.1 lxml 与 XPath 对齐教材 4.1 本章重点

安装：pip install lxml。lxml 是 C 实现的解析库，速度最快；它承载的 XPath（XML Path Language）是一门在树里"找地址"的语言——功能最强：能按属性找、按文本找、按位置找、按亲戚关系找。先建树的心智模型：

节点关系：把 408 的树搬进网页

关系含义XPath 写法例子（对 <h3 class="title"> 而言）
父 parent直接上一层.. / parent::<article class="item">
子 child直接下一层/ / child::（无，h3 没有子标签）
先辈 ancestor所有上层ancestor::article → section → body → html
后代 descendant所有下层（含孙辈）//（当前节点下）/ descendant::h3 里的文本节点
兄弟 sibling同父的左右节点following-sibling:: / preceding-sibling::<span class="score">（后兄弟）

对照书影快报的页面（游乐场里就有）：article 是 h3 与 span 的父，h3 与 span 互为兄弟，section.list 是它们的先辈，// 则"跳到任意层直接找"——这就是为什么推荐 //article[@class="item"] 而不是 /html/body/section/article：绝对路径一改版就断。

XPath 语法大表

类别写法含义 / 示例
路径/根节点起逐级下探：/html/body/div
//任意层级直取：//div[@class="item"]；当前节点下再任意层：.//a
谓词（筛选）[@class="x"]按属性精确匹配：//li[@class="item-0"]
[n] / [last()]第 n 个 / 最后一个（位置从 1 数起！）：//li[1]、//li[last()]
[position()<=3]前三个：//li[position()<=3]
通配与属性*任意元素：//div/*（div 的所有直接子元素）
@href取属性值：//a/@href、//img/@src
文本text()取节点的直属文本子节点，返回列表：//a/text()
string()把节点及其后代全部文本拼成一个字符串：string(//div)
谓词内用文本//a[text()="第一篇"] —— 按文字找节点，XPath 独有绝活
常用函数contains()包含匹配：//li[contains(@class,"item")]（防 class="item hot" 断配）
轴ancestor:: / descendant:: / following-sibling:: / preceding-sibling:: —— 沿亲戚关系游走
并集|两条路径合并：//a | //p

text() 与 string() 的区别（高频混淆点）

对 <p>你好<b>世界</b>再见</p>：//p/text() 只取 p 的直属文本，得到 ['你好', '再见']（b 里的"世界"不在此列，它属于 b 节点）；string(//p) 则递归收集 p 及其全部后代的文字，得到单个字符串 '你好世界再见'。经验法则：字段干净用 text()（返回列表），混着子标签用 string()（返回单值）。

解析与提取：两段代码跑通

xpath_demo.py
from lxml import etree

html = """
<div class="box">
  <ul id="list">
    <li class="item-0"><a href="/p/1.html">第一篇</a></li>
    <li class="item-1"><a href="/p/2.html">第二篇</a></li>
    <li class="item-2"><a href="/p/3.html">第三篇</a></li>
  </ul>
</div>
"""

tree = etree.HTML(html)                                # 字符串 → 节点树（自动补全 html/body）
print(tree.xpath('//li/a/text()'))
# ['第一篇', '第二篇', '第三篇'] —— text() 返回列表

print(tree.xpath('//li[@class="item-1"]/a/@href'))
# ['/p/2.html'] —— 属性也是节点，@href 直接取值

print(tree.xpath('//li[position()<=3]/@class'))
# ['item-0', 'item-1', 'item-2'] —— 谓词取前三个

print(tree.xpath('string(//li[@class="item-0"])'))
# 第一篇 —— string() 把该节点所有文字拼成一个字符串

第二段展示爬虫最常用的套路：从列表页提取 URL，跟进到下一层继续解析——树套树，两层 XPath：

xpath_follow.py
import requests
from lxml import etree

HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"}

# 第一层：列表页的树
resp = requests.get("https://quotes.toscrape.com/", headers=HEADERS, timeout=10)
tree = etree.HTML(resp.text)

links = tree.xpath('//div[@class="quote"]//span[2]/a/@href')   # 每条名言的作者页（相对路径）
for link in links[:3]:
    detail_url = "https://quotes.toscrape.com" + link          # 相对路径补全为绝对地址
    d = requests.get(detail_url, headers=HEADERS, timeout=10)
    dt = etree.HTML(d.text)                                    # 第二层：详情页再建一棵树
    name = dt.xpath('//h3[@class="author-title"]/text()')[0].strip()
    born = dt.xpath('//p[@class="author-born-date"]/text()')[0].strip()
    print(name, "|", born)

# 输出示例：
# Albert Einstein | March 14, 1879
# J.K. Rowling | July 31, 1965
# Albert Einstein | March 14, 1879

这个"列表页 → 详情页"的两层结构就是后续所有整站爬虫的骨架：第 02 章的正则负责一页内的硬捞，XPath 负责页面间的导航。

🌐 多源视角 · Mitchell《Python网络爬虫权威指南》：鲁棒解析三原则

Mitchell 在书里反复强调：解析代码的价值不在"今天能跑"，而在改版后的第三个月还能跑。她的工程习惯可以浓缩成三条：
· ① 解析结构，而非猜测字符串位置。位置（第几个标签、第几行）随改版漂移，结构（class 名、语义层级）稳定得多——这正是 XPath/CSS 选择器优于字符串切片与绝对路径的原因。
· ② 多选择器回退。主选择器失败就换备用，再不行还有按语义层级的兜底写法——站点改版通常只动一层，回退链能扛住大部分小改版。
· ③ 校验字段数与类型，解析失败要"响亮地失败"。宁可抛异常、发告警，也绝不把 None / 空串静默写进库——静默空数据是最贵的错误，等你发现时坏数据已经堆了一个月。

robust_parse.py —— 带回退与校验的解析函数
from lxml import etree
import logging

logger = logging.getLogger("spider")

def parse_article(tree):
    """② 多选择器回退：主选择器失败就换备用"""
    title = None
    for xp in ('//h3[@class="title"]/text()',      # 主：现在的结构
               '//h2[@class="title"]/text()',      # 备：改版后 h3 可能变 h2
               '//article//h3/text()'):            # 兜底：只认语义层级
        found = tree.xpath(xp)
        if found:
            title = found[0].strip()
            break

    scores = tree.xpath('//span[@class="score"]/text()')

    # ③ 校验：缺字段、类型不对就抛异常——响亮地失败，绝不静默返回空值
    if not title:
        logger.error("title 未命中，页面结构可能改版")
        raise ValueError("title 解析失败")
    if not scores:
        raise ValueError("score 解析失败")
    score = float(scores[0])              # 类型校验：转不动就抛 ValueError
    if not 0 <= score <= 10:
        raise ValueError(f"score 越界: {score}")
    return {"title": title, "score": score}

3.2 BeautifulSoup 对齐教材 4.2

安装：pip install beautifulsoup4 lxml。BeautifulSoup（简称 BS4）的 API 最符合人类直觉——"找标签、找属性、取文字"三个动作一目了然，代价是纯 Python 实现、大文件比 lxml 慢。它是个"外壳"，真正干活的是底下的解析器：

四种解析器对比

解析器传入写法速度容错备注
html.parser"html.parser"慢一般Python 内置，零依赖兜底
lxml（HTML）"lxml"最快好需 pip 安装 lxml，日常首选
lxml（XML）"xml"快严格只解析合规 XML / RSS，解 HTML 会报错
html5lib"html5lib"最慢最好以浏览器方式容错建树，页面烂到家时用

遍历：children / descendants / parent / sibling

bs4_demo.py
from bs4 import BeautifulSoup

html = """
<ul id="list">
  <li class="item-0"><a href="/p/1.html">第一篇</a></li>
  <li class="item-1"><a href="/p/2.html">第二篇</a></li>
</ul>
"""
soup = BeautifulSoup(html, "lxml")                 # 第二个参数永远显式指定解析器
ul = soup.find("ul", id="list")

# children：直接子节点 —— 注意换行符也是节点，要过滤！
for child in ul.children:
    if getattr(child, "name", None) == "li":
        print(child.a["href"], child.a.get_text(strip=True))
# /p/1.html 第一篇  /p/2.html 第二篇

# descendants：所有后代（递归）；parent：父节点；siblings：兄弟
print(len(list(ul.descendants)))              # 树上所有节点，含文本
first_li = ul.find("li")
print(first_li.parent.name)                    # ul
print(first_li.find_next_sibling("li").a["href"])   # /p/2.html —— 直接找下一个 li，避开换行节点

搜索：find / find_all 与 CSS 选择器 select

bs4_search.py
# find_all(name, attrs, string, limit)：返回列表；find 返回第一个
soup.find_all("li", class_="item-1")       # 按标签 + class（class_ 带下划线，避开关键字）
soup.find_all("a", href=True, limit=2)     # 有 href 属性的前 2 个
soup.find("li", attrs={"class": "item-0"}) # attrs 字典写法，属性名带连字符时必用
soup.find_all(string="第二篇")              # 按文本内容找

# select：CSS 选择器（和游乐场的 CSS 模式同一套语法）
soup.select("ul#list > li.item-0 a")       # 返回列表
a = soup.select_one(".item-1 a")            # 返回第一个

print(a["href"])                    # /p/2.html —— 取属性
print(a.get_text(strip=True))       # 第二篇 —— 取文本并去首尾空白，最常用
BS4 使用心法：定位用 select/select_one（CSS 语法最顺手），批量提取用 find_all，取文本一律 get_text(strip=True)，取属性用 tag["attr"]。复杂条件（按文本找、按位置找）做不了时，就是该换 XPath 的信号。
🌐 多源视角 · Mitchell《Python网络爬虫权威指南》：脏 HTML 与编码黑魔法

教程里的 HTML 永远规整，真实页面永远"脏"，Mitchell 在书里花了大量篇幅对付它们。真实页面的脏可归为三类：未闭合标签（<p> 忘了 </p>）、非法嵌套（<ul> 里直接塞 <div>）、隐藏字符——最阴险的是零宽空格 \u200b（看不见、strip() 剥不掉，但会让字符串比较失败）和不间断空格 \xa0（&nbsp;，相等比较与计数时的隐形杀手）。对策双管齐下：结构交给容错解析器修复（BS4 + lxml / html5lib），字符交给清洗函数。编码方面，BeautifulSoup 内置探测器 UnicodeDammit：喂给它 bytes，它按字节特征猜编码并转成 unicode，猜中的源编码会记在 soup.original_encoding 里——响应头没声明 charset 的老站，这一招能救命。

clean_html.py
import re, unicodedata
from bs4 import BeautifulSoup
from bs4.dammit import UnicodeDammit

# ① 结构脏：p 忘了闭合 —— lxml 解析器自动补全，选择器照样能用
dirty = '<div><p class="price">￥45.5<span>实付</span></div>'
soup = BeautifulSoup(dirty, "lxml")
print(soup.select_one(".price").get_text())     # ￥45.5实付 —— 结构已被修复

# ② 编码脏：拿到一段没声明编码的字节，UnicodeDammit 自动探测并转成 unicode
dammit = UnicodeDammit("你好".encode("utf-16"))
print(dammit.unicode_markup)                   # 你好 —— 带 BOM 时不用猜，直接命中

# ③ 字符脏：零宽字符、&nbsp;、全半角、连续空白，一个清洗函数全部处理
def clean_text(s):
    s = s.replace("\u200b", "")                # 零宽空格：删
    s = s.replace("\xa0", " ")                 # 不间断空格 → 普通空格
    s = unicodedata.normalize("NFKC", s)       # 全角→半角：ＡＢＣ１２３ → ABC123
    s = re.sub(r"\s+", " ", s)                 # 连续空白折叠成一个
    return s.strip()

3.3 pyquery 对齐教材 4.3

安装：pip install pyquery。如果你写过 jQuery 或前端，pyquery 会让你瞬间上手：CSS 选择器 + 链式调用，$ 换成 pq：

pyquery_demo.py
from pyquery import PyQuery as pq

doc = pq(resp.text)                          # 也可以 pq(url) 直接请求、pq(filename=...) 读文件

print(doc("ul#list .item-0 a").text())      # 第一篇

for item in doc("li").items():              # items() 把每个元素包成小 PyQuery，可继续链式
    print(item.attr("class"), item("a").attr("href"), item.text())
# item-0 /p/1.html 第一篇 …

# 链式过滤：先取 li，再筛 class，再下钻
href = doc("li").filter(".item-1").find("a").attr("href")
print(href)                                  # /p/2.html

什么时候顺手：有 jQuery 肌肉记忆、想做"先圈大范围再层层过滤"的链式操作时。注意它的底层也是 lxml，但 XPath 的复杂谓词、轴、按文本定位它表达不了——那些场景老老实实回 3.1。

3.4 parsel：Scrapy 同源的工程首选 拓展

安装：pip install parsel。parsel 是 Scrapy 框架内置的提取库（第 10 章你会再遇到它），最大特点是 xpath 与 css 一体两面——同一棵树上两种语法随意接力，返回的选择器对象是惰性的，链到最后才真正取值：

parsel_demo.py
import parsel

sel = parsel.Selector(resp.text)

print(sel.xpath('//ul[@id="list"]/li/a/text()').getall())
# ['第一篇', '第二篇', '第三篇'] —— getall()：所有结果列表

print(sel.css("ul#list li.item-1 a::attr(href)").get())
# /p/2.html —— get()：第一个结果（没有就返回 None，不会 IndexError）

# 两种语法在同一棵树上接力：XPath 圈范围，CSS 取属性
print(sel.xpath('//li[contains(@class,"item")]').css("a::text").getall())

for li in sel.xpath('//li'):                # 单节点也是 Selector，可继续 xpath/css
    print(li.xpath('./a/@href').get(), li.xpath('string(.)').get())

新 API 记住两个词就够：get() 取一个、getall() 取全部（旧的 extract_first() / extract() 仍兼容但已过时）。它最大的优势是"跟 Scrapy 同源"——现在用 requests + parsel 写的解析函数，第 10 章可以原样搬进 Scrapy 的 Spider。

3.5 JSON 数据解析 拓展

接口返回的数据大多是 JSON（第 05 章会大量遇到），Python 标准库 json 就够用。两个高频参数：ensure_ascii=False 让中文原样输出（默认会把中文转义成 \u4f60），indent 美化缩进（文件会变大，落库时不加）：

json_demo.py
import json

item = {"title": "三体", "score": 9.3, "tags": ["科幻", "小说"]}

text = json.dumps(item, ensure_ascii=False, indent=2)   # dict → str（序列化）
print(text)
# {
#   "title": "三体",
#   "score": 9.3,
#   "tags": ["科幻", "小说"]
# }

data = json.loads(text)                                   # str → dict（反序列化）
print(data["tags"][0])                                    # 科幻

爬虫存 JSON 的最佳姿势是 JSON Lines：每行一个独立 JSON 对象，追加写不断不裂——断点续爬时直接续着写，读取时逐行流式解析，某一行坏了也不影响其余数据：

jsonl_demo.py
import json

# 写：a 追加模式，每条一行以 \n 结尾
with open("items.jsonl", "a", encoding="utf-8") as f:
    for item in [{"title": "三体", "score": 9.3}, {"title": "活着", "score": 9.4}]:
        f.write(json.dumps(item, ensure_ascii=False) + "\n")

# 读：逐行流式，坏一行跳一行
with open("items.jsonl", encoding="utf-8") as f:
    for line in f:
        if line.strip():
            try:
                print(json.loads(line)["title"])
            except json.JSONDecodeError:
                continue
# 三体  活着

3.6 选择器的可维护性：防改版设计 拓展

写选择器只看"今天命中"，是玩具和工程的最大分水岭。先亮性能底牌（同一页面提取同一批字段的大致量级对比）：

方案速度量级可维护性适用
正则视模式而定：简单模式极快，复杂模式回溯可能失控（见 2.3 边界）差——表达式与页面结构脱节，改版要重新找规律压缩文本、JS 变量的最后兜底
BeautifulSoup慢（纯 Python，比 lxml 慢一到两个数量级）好——API 最友好小脚本、一次性提取
lxml / XPath（parsel）最快（C 实现）好——表达式即结构正式项目、批量任务、Scrapy

速度可以花钱换机器，改版只能靠设计扛。防改版三板斧：① 多级回退选择器——每级都写清"应对哪种改版"；② 字段校验——数量、类型、取值范围；③ 结构变更告警——抓不到就报警，绝不静默返回空数据（等你发现"库里一个月没新数据"时，损失已经造成）。

parse_with_fallback.py
import logging
from lxml import etree

logger = logging.getLogger("spider")

# 三板斧之一：多级回退选择器——每级注明"为什么会有这一级"
TITLE_XPATHS = [
    './/h3[@class="title"]/text()',   # 主：当前结构
    './/h2[@class="title"]/text()',   # 备：h3 被改成 h2
    './/h3/text()',                   # 兜底：class 变了只剩语义层级
]

def parse_with_fallback(html, base_url=""):
    tree = etree.HTML(html)
    items = []
    for art in tree.xpath('//article[@class="item"]'):
        title = None
        for xp in TITLE_XPATHS:               # ① 多级回退
            hit = art.xpath(xp)
            if hit:
                title = hit[0].strip()
                break
        score = art.xpath('.//span[@class="score"]/text()')
        if not title or not score:             # ② 字段校验：缺了就跳过这条
            continue
        items.append({"title": title, "score": float(score[0])})

    # ③ 结构变更告警：列表页每页应稳定命中预期条数，骤降即报警
    if len(items) < 5:
        logger.error("【结构告警】%s 仅解析出 %d 条（预期 10 条左右），页面可能已改版",
                     base_url, len(items))
    return items
设计心法：回退链是"缓存"，告警是"保险丝"——回退兜住了小改版，告警保证大改版第一时间被发现。两者合起来，才配叫"可维护的选择器"。
本章避坑清单：① XPath 位置从 1 数起：//li[1] 是第一个元素，不是第二个——和 Python 下标 [0] 相反，翻页/取第 N 条时最容易栽；② text() 返回列表，直接 [0] 会在结构变动时 IndexError——先判空，或用 parsel 的 .get()（无结果返回 None）；③ BS4 的 children/next_sibling 会把换行符当文本节点混进来——用 find_next_sibling("li") 按标签找，或 getattr(x, "name", None) 过滤；④ BeautifulSoup(html, "lxml") 没装 lxml 会抛 FeatureNotFound，用 "xml" 解析 HTML 也会莫名报错——解析器参数永远显式写对；⑤ requests 拿到的永远是原始 HTML：Elements 面板里 JS 塞的内容不在里面（呼应 1.2），解析不到先想"数据在不在源代码里"，别怀疑选择器写错。

from lxml import etree

tree = etree.HTML(html)
# 在售书名：排除 soldout —— 谓词筛 li，再下钻取 b 的直属文本
print(tree.xpath('//li[@class="book"]/b/text()'))          # ['三体', '活着']
print(tree.xpath('//li[@class="book"]/span[@class="price"]/text()'))   # ['45.0', '28.0']
print(tree.xpath('//li[@class="book"]/@data-id'))          # ['1', '2']
print(tree.xpath('//li[@class="book"][1]/b/text()'))       # ['三体'] —— 位置谓词从 1 数起

# 工程更稳的写法：contains 防 class 变成 "book hot"，并成对提取
for li in tree.xpath('//li[contains(@class,"book")]'):
    print(li.xpath('@data-id')[0],
          li.xpath('./b/text()')[0],
          li.xpath('./span[@class="price"]/text()')[0])
# 1 三体 45.0   2 活着 28.0

          注意别写 //li/b/text()——绝版书会被混进来；也不要写死绝对路径 /html/body/div/ul/li[1]/b，改版即断。

        

      


      
Q2text() 与 string() 的区别是什么？对 <p>你好<b>世界</b>再见</p> 分别会得到什么？各自适用什么场景？概念
        

          
考点：3.1 高频混淆点，直接决定提取结果的完整性。

          
参考解析：text() 只选取该节点直属的文本子节点（不含子标签内部的文字），返回列表：//p/text() → ['你好', '再见']，"世界"属于 b 节点、被漏掉。 string() 递归收集该节点及其全部后代的文字，拼接成单个字符串：string(//p) → '你好世界再见'。选型经验：字段文本干净、要逐个处理时用 text()（配 findall/getall 循环）；节点里混着子标签、要整段文字时用 string()——比如取"包含 <b> 加粗价格的商品描述"。BS4 里对应的是 get_text()（等价 string 的语义），这也是两套库互相迁移时的关键对照。

        

      


      
Q3BeautifulSoup 和 XPath（lxml/parsel）各有什么优劣？给出你的选型标准，并说明什么信号出现时应该换工具。分析
        

          
考点：3.1~3.4 的横向对比与工程判断力。

          
参考解析：BS4 优势：API 最友好、find_all/select 语义直白、容错好（html5lib 兜底），适合小脚本和临时提取。XPath 优势：功能强（按文本定位、位置谓词、轴、并集）、速度快（lxml C 实现）、parsel 还能 get()/getall() 防空、与 Scrapy 同源，适合结构复杂、批量、要长期维护的工程。选型标准一句话：简单页面/一次性任务用 BS4，复杂结构/正式项目用 XPath（parsel），两者也可以在同一项目混用。换工具的信号：① 需要"按文本找节点"或"取前 N 个兄弟"这类 BS4 表达不了的条件；② 发现自己在写三层 for 循环人工过滤——XPath 谓词一行搞定；③ 大文件解析明显变慢；④ 准备迁移到 Scrapy。反之，如果 XPath 表达式已经长得像天书而需求只是"取一个标题"，BS4 一行 select_one 更清爽。

        

      


      
Q4动手：为爬虫设计一对 JSON Lines 存取函数 save_jsonl / load_jsonl，并说明为什么比"把整个列表一次 json.dump"更适合爬虫场景。动手

参考解析：


import json

def save_jsonl(path, item):
    """追加一条：断点续爬随时可停，重启接着写"""
    with open(path, "a", encoding="utf-8") as f:
        f.write(json.dumps(item, ensure_ascii=False) + "\n")

def load_jsonl(path):
    """逐行流式读取：坏一行跳一行，不毁整个文件"""
    items = []
    with open(path, encoding="utf-8") as f:
        for line in f:
            if line.strip():
                try:
                    items.append(json.loads(line))
                except json.JSONDecodeError:
                    continue
    return items

save_jsonl("items.jsonl", {"title": "三体", "score": 9.3})
print(load_jsonl("items.jsonl"))    # [{'title': '三体', 'score': 9.3}]

          
相比"攒一个大列表再 json.dump"：① 追加安全——a 模式每行独立，爬到 8 万条时崩溃也不丢前 79999 条；② 断点续爬——重启直接续写，无需读出旧数据再合并；③ 流式解析——内存里永远只有一行，适合大数据量；④ 容错——某行被写坏只损失一条，整文件 dump 则一坏全坏。这正是第 04 章"文件存储选型"里 JSON Lines 的核心价值。
